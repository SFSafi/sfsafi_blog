# FFmpeg 视频转码服务

已实现独立 Python/FFmpeg 服务和站主管理页面 `/admin/media/`，并非在 Cloudflare Worker 内运行 FFmpeg。当前 R2 尚未建立，转码结果保存在独立服务的持久卷，仅通过站主认证的管理接口访问；不能插入正文、不能公开播放，也未宣称已上线真实服务器。Codex 临时机器不作为持久媒体服务器。

## 功能

- 选定文件即自动上传并创建任务，默认标准档、不保留原素材；高质量 1080p/CRF21、标准 720p/CRF25、省空间 480p/CRF29，不放大素材，保持比例、纠正视频旋转，偶数尺寸。
- 真实 H.264/yuv420p + AAC MP4，faststart，JPEG 封面；移除派生视频元数据，验证输出轨道、音频和时长。编码受超时、分辨率、输入大小与输出大小约束；无法保证每个文件变小，界面展示真实大小及存储总量。
- 原素材选项保留原始字节；兼容的 H.264/yuv420p + AAC MP4 直接作为播放源，通过硬链接避免重复存储，不重新编码或承诺体积减少；其他格式另生成标准播放版本。压缩档也可额外保留源文件。默认只有校验完成、任务结果持久化后才清理本次临时源文件；失败源文件保持私有，需运维检查清理，不自动删除其他任务或用户本地文件。
- SQLite 持久任务队列，单进程、单转码工作线程，最多 4 个未完成任务；重启恢复处理中任务，最多处理 3 次，避免资源不足造成无限重启；上传中断标记失败。页面 URL 保存任务 ID，可稍后返回查看。
- 仅站主 Access JWT + OWNER_EMAIL 验证后代理；服务密钥只存在 Worker Secret 和服务环境变量。视频支持 HTTP Range，原素材强制下载，无公开目录或客户端密钥。
- 文件限 64 MiB / 10 分钟 / 每边 7680 像素且总像素不超过 3400 万；输出最多 256 MiB，超出后完整性检查会拒绝截断输出。暂不支持超过这些限制的视频、图片压缩、批量上传、暂停续传或取消正在执行的转码；页面取消仅取消 HTTP 上传。

## 部署到你已有的 Linux 服务器

需要 Docker Compose、持久磁盘和可供 Worker 访问的 HTTPS 地址，例如 `transcode.sfsafi-blog.uk`。不要在 Workers & Pages 中部署此 Python 服务，不需要为此开启 Cloudflare 付费容器。

1. 在服务器上取得本仓库，进入 `transcoder/`。在服务器本地用 `openssl rand -hex 32` 生成随机密钥，将其写入本目录 `.env` 的 `TRANSCODER_TOKEN`。不要提交或发到聊天。
2. 执行 `docker compose up -d --build`。配置限定 2 CPU / 1 GiB 内存、非 root、只读根文件系统、持久 `media` 卷，端口只绑定服务器的 `127.0.0.1:8090`。只能运行一个实例访问该卷；不要启动多个副本。
3. 用已有 HTTPS 反向代理或 Cloudflare Tunnel 将上述主机名转发至本地端口。设置上传限制不低于 64 MiB、上传超时至少 120 秒；不要增加页面邮箱 Access 挑战，否则 Worker 服务请求无法通过。服务本身始终校验 Bearer 密钥，主机名可访问不代表文件公开。
4. 博客 Worker 控制台添加 Text `TRANSCODER_URL=https://transcode.sfsafi-blog.uk` 和 Secret `TRANSCODER_TOKEN`（与服务相同）。地址不带路径；保存部署。现有 `ACCESS_TEAM_DOMAIN`、`ACCESS_AUD`、`OWNER_EMAIL` 仍须完成。
5. 登录 `https://sfsafi-blog.uk/admin/media/`，上传一段有声音的视频，检查三个档位、声音、时间轴拖动、原素材 SHA-256 和页面刷新后的结果。未经真实服务器验收，不称生产转码已启用。

没有服务器时，服务代码可先保留，站点明确提示未配置。FFmpeg 没有按次转码费用；计算、磁盘、备份和网络费用取决于你选择的服务器。本轮未购买服务器、未启用付费服务。

## 本地检查与维护

安装 Python 3.11+、`ffmpeg`/`ffprobe`，运行 `python -m unittest discover -s transcoder -p 'test_*.py' -v`。测试真实编码、档位差异、音轨、faststart、封面、原素材校验和、鉴权、Range、任务持久化和源文件清理，不用模拟编码结果。

备份整个持久卷（视频、原素材和 jobs.sqlite），不要只备份数据库。建议先停止服务进行一致备份；更新 FFmpeg 安全补丁并监控剩余磁盘，失败任务保留的源文件可能持续占用空间。不要自动删除已完成任务或卷。服务拒绝网络输入协议/播放列表，仍建议保持隔离和 FFmpeg 补丁更新。

后续建立 R2 后，需要增加已验证派生对象上传、草稿访问控制、媒体与正文绑定、发布后公开读取和撤回后隔离，完成这些后才可称正文视频上传正式接通。
