# 评论回复邮件

评论无需审核，提交后立即显示；仅站主可在 `/admin/comments/` 删除。删除保留评论管理记录，同时移除该评论/子回复的邮箱并取消待发通知；文章撤回或目标评论不可见时不再投递。历史 pending 评论按公开处理，已有 hidden/deleted 保持隐藏。

## 访客流程

1. 昵称、评论必填，邮箱选填。不填写邮箱仍可正常发布；邮箱不会出现在公开接口、HTML、管理评论列表或浏览器 localStorage。
2. 填写邮箱后，评论立即显示，系统把确认邮件加入队列。打开确认链接后还需点击确认按钮，24 小时内有效；邮箱未确认前不发送回复通知。已经在同一访客会话确认过的同一邮箱可复用确认。
3. 当前支持一级回复。其他访客或站主回复你的一级评论后，收到通知；回复自己的评论不发邮件。邮件包含纯文本回复与对应评论链接。
4. 每封邮件含这条评论的退订链接，打开后点击退订；邮箱被移除，待发通知取消。邮件链接不授予后台权限，自动链接扫描不会修改订阅。

未配置服务时，邮箱输入框禁用并明确提示，评论照常公开；不收集当前无法使用的邮箱。格式错误、频率限制、邮件发送失败均不伪装成已送达。

## 站主配置（Cloudflare 网页）

本次仅实现代码/受控协议测试，没有创建 Resend 账号、购买套餐或发送真实邮件。

1. 在 [Resend](https://resend.com/) 创建账号，添加并验证你的发件域名（例如 `sfsafi-blog.uk` 或单独的发信子域名）。把 Resend 给出的 DNS 记录添加到 Cloudflare，并等待验证通过；不要覆盖已有 MX/SPF 记录。发信域名验证与 Cloudflare Access 登录是两件事。
2. 创建仅发送用途的 API Key。在 Cloudflare → Workers & Pages → sfsafi-blog → Settings → Variables and Secrets，添加：

| 类型         | 名称                 | 内容                                                          |
| ------------ | -------------------- | ------------------------------------------------------------- |
| Secret       | `RESEND_API_KEY`     | Resend 发信 API Key，不要提交 Git 或发到聊天                  |
| Secret       | `EMAIL_TOKEN_SECRET` | 用密码管理器生成至少 32 个随机字符，用于邮件确认/退订链接签名 |
| Text         | `EMAIL_FROM`         | 已验证域名的地址，例如 `SFSafi <notify@sfsafi-blog.uk>`       |
| Text         | `SITE_URL`           | `https://sfsafi-blog.uk`                                      |
| Text（可选） | `MAIL_DAILY_LIMIT`   | 默认 100 次发送尝试/北京时间每天，允许 1–1000；设 0 暂停通知  |

站主主邮箱 `jonce_z@126.com` 继续用于身份校验；不能直接把 126.com 当作自己可验证的发件域名。这里的发件地址只需在 Resend 的已验证域名下，不要求先创建独立收件邮箱。

3. 保存部署。当前网站已有每 5 分钟运行的 Cron，邮件每次最多处理 2 个任务；少量评论通常几分钟内发送，有积压或触发额度时更慢。Resend 账号的套餐/实际限制以其控制台为准，代码限额不会替你升级套餐。
4. 用你自己控制的邮箱发表评论、确认订阅，再从后台回复，检查邮件和退订。只验证自有邮箱，不用其他人的地址做测试。未完成此步骤，不称真实邮件已送达。

## 状态与持久化

新增 `0007_comment_email.sql` 仅新增私有邮箱与邮件任务表，自动初始化，不修改已有评论表结构或覆盖原数据。默认的新评论由 API 显式写入 approved；旧建表默认 pending 不再形成审核门槛。

任务与评论/回复在同一 D1 批事务保存，唯一任务 ID 防重复；发信采用服务端密钥与 Resend Idempotency-Key，不提供任意收件人或任意邮件正文的公开发送接口。每个邮箱最多每小时两次新确认请求，另保留评论原有限流及全站邮件每日预算。

后台评论管理显示邮件队列计数：待发送、发送中、服务已接收、失败、结果不确定、已取消。服务已接收意味着返回有效发送 ID，不代表收件箱一定收到；当前没有接入送达/退信 Webhook。

仅明确 429 自动退避重试，最多 3 次；网络异常、5xx、缺少有效发送 ID 或发送中进程中断记为 uncertain，不盲目重发。超过 24 小时的排队任务取消，未确认邮箱到期移除；失败/uncertain 的任务保留诊断状态，当前没有人工重发按钮。配置错误先修正配置并用自有邮箱重新验证，不要直接批量重置 uncertain，否则可能重复发送。

Secrets 不写入日志，地址/正文/签名链接/供应商响应体也不写入日志。私有邮箱仍存于 D1，数据库备份应按私有数据管理。

官方接口：[发送邮件](https://resend.com/docs/api-reference/emails/send-email)。
