# Astro 个人空间：Codex 云端搭建技术任务书

版本：1.0 ｜ 日期：2026-10-13 ｜ 文档性质：实施需求与验收依据

## 1. 项目目标与执行指令

使用 Astro 搭建由站主单人发布、访客浏览的 SNS 风格个人空间。站主负责功能与外观定义，Codex 负责项目初始化、开发、验证、部署配置和维护文档。所有开发工作在云端进行，不能要求站主在本地安装 Node.js、编辑器、下载仓库或运行命令。

收到本文档后，Codex 应先检查当前仓库和开发环境，随后实际创建或修改项目。不要只回复方案或示例代码。已有文件和已有网站必须先检查，不能直接覆盖。本文档不指定迁移已有网站；若需要导入旧内容，应另行确认来源。

默认推进到第一阶段可运行界面并提供预览，等待站主确认外观后推进真实后台。常规、可逆的技术选择自行决定；服务付费、正式公开发布、删除已有数据及会显著改变用户体验的需求歧义需要站主确认。一次集中提出必要问题，并继续不依赖答案的工作。

## 2. 范围与阶段

| 阶段 | 交付范围 | 完成标志 |
| --- | --- | --- |
| A：界面原型 | Astro 工程、动态流、详情、关于我、主题切换、多媒体展示 | 可打开预览，移动端检查通过，外观得到确认 |
| B：真实内容管理 | 登录、草稿、图文与视频上传、编辑、发布、撤回、持久化 | 完成真实发布与权限验收 |
| C：部署与运维 | 正式托管、自动部署、备份、回滚、域名配置 | 站主可以通过浏览器独立维护内容 |
| D：评论扩展 | 评论、回复、审核、反垃圾与删除 | 评论权限与审核测试通过 |
| E：QQ 订阅扩展 | 订阅、退订、筛选、更新推送、去重与重试 | 支持范围确认后完成真实端到端验证 |

第一版必须完成 A、B、C。D、E 是后续扩展，本次先设计必要的接口与稳定 ID，不提前建设复杂社交平台。第一版不包含公众注册发帖、关注关系、私信、推荐算法、点赞系统。

## 3. 使用场景与页面

### 3.1 公开页面

- 首页：个人介绍、导航、按发布时间倒序的动态流；置顶动态单独排序；支持分页或“加载更多”，不得一次加载全部历史内容。
- 动态详情：正文、图片组、视频、标签、首次发布时间、更新提示、可分享的稳定链接；未来可以挂载评论区。
- 文章列表与文章详情：适合工程笔记、长文，具备标题、摘要和良好阅读排版。
- 关于我：头像、简介、联系方式或外部链接；内容可由后台编辑。
- 标签页：按标签浏览已发布内容。
- 相册页列为可选，完成核心流程后再决定，不能阻塞第一版。
- 未找到页面与加载失败提示：清晰说明情况，提供返回入口。

### 3.2 管理后台

站主通过手机或电脑浏览器登录后台，新建文字动态、图文动态、视频动态或长文；上传媒体、预览、保存草稿、发布、修改、撤回为草稿，以及明确确认后的删除。第一版正文可采用 Markdown 编辑器配预览，不强制自行编写富文本编辑器。CMS 后台与前台可以是独立应用。

上传需要进度、失败原因和重试入口；发布需要显示成功或失败，避免重复点击造成重复内容。界面确认阶段允许示例数据，但不能把模拟保存、localStorage 或内存数据标成真实内容管理。

## 4. 外观与交互要求

- 手机优先，检查 360、390、768、1440 像素宽度；正文与操作按钮不出现横向溢出。
- 字体使用 MiSans。确认授权和字体来源，优先合理子集化的 WOFF2 或可变字体，提供系统字体回退，不因字体加载失败阻塞阅读。
- 正文字号初始参考 16–18px、行高 1.65–1.8、字重约 500；最终由站主预览确认，避免全站粗体。
- 至少提供浅色、深色、一个彩色主题；颜色通过 CSS 变量统一维护。支持跟随系统及记住访客的主题选择。
- 动态使用卡片或轻分隔布局，不堆积无关装饰；桌面限制正文最大宽度，保持易读。
- 单图保留比例；多图支持网格，缩略图裁切规则需明确，点击后必须显示完整原图。图组支持上一张、下一张、关闭、键盘操作和合理焦点管理。
- 视频默认不自动播放；提供封面、播放控件、内联播放、合理预加载策略。避免动态列表同时下载所有完整视频。
- 按钮具有可读标签，键盘可操作，颜色对比可辨；提供空状态、错误状态和提交中状态。

## 5. 技术架构与决策

### 5.1 默认方向

前台采用 Astro + TypeScript，以 Astro 组件和 CSS 为主；复杂交互仅在需要的局部引入交互组件，避免把整个网站改成 SPA。开发环境、正式网站、数据库与媒体存储相互独立。开发任务关闭不影响正式网站与机器人运行。

内容通过统一的 ContentRepository 接口读取。初期可用本地示例数据；真实阶段接 CMS 或数据库适配器。Astro Content Collections 可用于校验与加载，但不把特定目录或某个 CMS 的字段结构写死在所有页面中。

### 5.2 CMS 与渲染方式选择

在 B 阶段编码前，Codex 根据当前官方资料比较至多两种可行方案，提交推荐方案及理由，包括手机编辑、媒体上传、费用、登录配置、备份迁移和维护成本。不强制指定服务品牌。优先成熟 CMS，避免无必要地从零编写管理后台。

| 方案 | 内容更新方式 | 必须解决的问题 |
| --- | --- | --- |
| 静态前台 + CMS | 发布后触发构建，成功部署后可见 | 构建延迟、Webhook、草稿隔离、预览认证、部署成功通知 |
| 按需渲染/混合 + CMS 或数据库 | 请求时读取内容，可配缓存 | Astro 部署适配器、服务端认证、缓存失效、运行费用 |

若选择静态方案，草稿预览必须通过 CMS 内部预览或受保护的服务端能力实现；不能把草稿 HTML、JSON 或媒体私密地址打进公开构建。若要求发布立即可见，应采用可支持该需求的渲染与缓存方案。服务名、套餐、限制、接口和版本在实施时核实，不沿用未经验证的旧教程。

### 5.3 媒体

真实上传使用持久化媒体存储；大量图片和视频不得存入 Git，也不能留在 Codex 云端临时目录。通过 CMS 上传能力或服务端签发的短期上传凭证上传，不能向浏览器暴露管理密钥。文件类型、容量、数量上限由选定服务能力和预算决定，并在上传前后校验。

上传支持原素材、高质量、标准、省空间选项；选择原素材时保留原文件字节，选择压缩时可另外选择同时保留原素材，不默认保存所有原始文件。保存实际选择的媒体版本、派生缩略图、尺寸和描述信息；封面与图片使用响应式资源和延迟加载。第一版不默认建设视频转码集群，说明支持的浏览器格式和实际上传限制。不把整站承诺为无限容量。

### 5.4 后端与运行环境

认证、管理员写操作、Webhook、未来评论和推送在受支持的服务端执行。无服务器平台适合短请求；需要长期连接或常驻进程的机器人必须选择对应运行环境。不能把开发服务器当作正式托管或常驻 Bot。

## 6. 数据契约

以下为逻辑模型，实际存储可以采用 CMS 字段或数据库表。不要为未启用扩展提前建立全部运行基础设施。

### 6.1 内容 Post

| 字段 | 规则 |
| --- | --- |
| id | 稳定唯一 ID，标题、正文、标签修改不得改变 |
| kind | note 或 article；图片和视频是内容附属媒体，不必拆成独立类型 |
| title | 长文章必填，短动态可选 |
| body / bodyFormat | 正文及明确的 Markdown/富文本格式 |
| excerpt | 可选摘要；用于列表和推送，避免直接发送完整正文 |
| status | draft、published、archived；公开查询只返回 published |
| visibility | 第一版默认 public；保留扩展字段，不提供未实现的私密承诺 |
| media | 有序媒体引用，保留混合图片视频的排列顺序 |
| tags | 规范化标签 |
| pinned | 是否置顶 |
| createdAt / updatedAt | UTC 时间，页面按明确时区显示，默认 Asia/Shanghai |
| firstPublishedAt | 第一次发布时设置，编辑、撤回、重新发布不重置 |
| revision | 内容版本，用于并发修改与预览/部署追踪 |
| canonicalPath | 稳定链接，推荐 /posts/{id}，更换标题不导致失效 |

若使用可读 slug，必须保留旧地址重定向，且评论和订阅内部仍关联 id。删除内容要考虑旧链接、关联评论与媒体引用，优先可恢复删除或归档。

### 6.2 媒体 Media

id、storageKey、kind、mimeType、byteSize、width、height、duration（视频）、alt、caption、thumbnailKey、processingStatus、createdAt。公开 URL 由适配器生成，不把可能过期的签名 URL 当作永久存储标识。媒体删除前检查其他内容是否引用。

### 6.3 发布事件

事件至少包含 eventId、postId、revision、eventType、occurredAt。区分首次发布、普通编辑、撤回、归档以及重新发布。默认仅首次发布触发更新订阅；其他事件不自动推送，后续若增加“通知订阅者”需明确选择。

静态模式区分“内容已提交发布”和“该版本已在线可访问”。发送推送前必须确认对应 postId/revision 已上线，不能只判断任意一次部署成功。

## 7. 评论扩展设计（阶段 D）

评论关联稳定 postId；服务选型时说明访客是否需要外部账号，不能默认站主接受强制 GitHub 登录。

最小功能：发布评论、回复、分页、管理员隐藏/删除、待审核状态、速率限制与基础反垃圾。正文按安全规则渲染，禁止执行访客输入的脚本。评论状态至少包含 pending、approved、hidden；公开 API 只返回可公开评论。

逻辑字段：id、postId、parentId、authorIdentity、displayName、body、status、createdAt、updatedAt。身份信息和联系信息不应随着公开评论 API 全部泄露。管理员审核与删除必须由服务端授权。

验收需覆盖：未登录管理员不能管理评论；未审核内容不公开；危险 HTML 不执行；回复准确关联；被删除/撤回内容的评论行为有明确规则。

## 8. QQ Bot 订阅扩展设计（阶段 E）

### 8.1 实施前核实

本文件不保证 QQ 某一种接口具备任意主动推送能力。Codex 必须在实施前阅读所选机器人平台当前官方资料，确认支持的 QQ 群、个人或其他渠道、申请与审核条件、用户交互要求、主动发送限制、频率、消息格式和云端运行方式。给出来源和验证日期。

站主需确认目标是指定群推送、个人订阅或二者。优先支持的官方方案；若官方能力不满足，不静默换成个人账号协议方案，也不把替代渠道当作 QQ 已实现。应说明缺口与可行选择后再实施。

### 8.2 用户流程

用户在受支持的机器人会话中执行订阅、退订、查看订阅，后续可按标签筛选。以机器人事件验证发送者与会话身份，不接受未验证的任意 QQ 号码作为发送目标。群订阅必须具有明确授权机制，不把单个成员操作默认视为群整体授权。

推荐指令语义：订阅全部、订阅标签、查看订阅、取消订阅。实际指令格式按平台能力设计。第一版 Bot 不读取或推送草稿、私密内容。

### 8.3 推送流程与可靠性

内容上线确认 → 创建持久化事件/待发任务 → 按有效订阅筛选 → 调用发送适配器 → 保存结果。使用持久队列或数据库任务表，不依赖一次 HTTP 请求中的内存循环。

- 订阅字段：id、channel、targetType、providerScopedTargetId、tagFilter、status、createdAt、unsubscribedAt。
- 投递字段：eventId、subscriptionId、state、attemptCount、nextAttemptAt、providerMessageId、lastError、sentAt。
- 为 eventId + subscriptionId 建立唯一约束；默认一次首次发布事件仅创建一次对应投递。
- 支持指数退避、最大重试次数、失败记录及管理员重试，遵循平台频率限制。
- 每次发送前再次检查内容仍公开且订阅仍有效；退订后尚未发送的任务跳过。
- 网络超时可能导致“平台已发送但客户端未知”；使用平台幂等机制（若有），否则记录不确定状态，避免承诺绝对恰好一次发送。
- Webhook 验签、处理重放、重试和乱序；仅可信系统可以生成上线事件。
- 消息默认包含标题或短摘要、少量允许的媒体、稳定网页链接；视频优先发送网页链接。

提供 NotificationProvider 抽象，QQ SDK 与核心发布流程解耦，支持未来增加其他通知渠道，但只实现本阶段确认的渠道。

## 9. 云端开发与仓库约定

站主通过网页创建 Git 仓库并授权 Codex 云端环境。Codex 检查运行时版本、包管理器、网络访问、仓库权限，完成依赖安装、构建和预览配置。环境入口会随产品界面变化，以实际账号能力为准。环境发布和网站正式发布是两个独立动作。

- 使用一个包管理器，提交锁文件；CI 与云端环境使用一致的受支持运行时版本。
- 主分支保留可用版本，阶段开发使用分支，提供清晰提交或 PR。重要成果及时推送，不依赖任务临时状态。
- 同一阶段优先继续原任务；切换任务前提交代码并更新进度文档。
- 配置环境变量示例但不包含真实密钥。凭据通过平台安全配置接入。
- 预览必须是站主可打开的页面；不能仅报告 localhost 地址。若运行环境不能对外暴露预览，配置托管平台的预览部署，并说明访问范围。
- 公开预览仅包含示例或允许公开的内容；认证后台与草稿预览不因预览部署而公开。
- 正式域名、生产部署、CMS 数据和媒体存储不依赖 Codex 开发环境寿命。

建议仓库文档：README.md、AGENTS.md、docs/requirements.md、docs/architecture.md、docs/progress.md、docs/deployment.md、docs/operations.md。本文件内容可拆入这些文件，但需求含义必须保留。

## 10. 分阶段执行任务

### A：工程与界面

1. 检查仓库；初始化 Astro/TypeScript；写明实际选用版本。
2. 创建统一数据接口、示例动态、文章与媒体，不引入真实生产账号依赖。
3. 完成公开页面、手机布局、MiSans、主题、多图查看与视频展示。
4. 检查正常、空、错误状态以及基本键盘操作，运行构建。
5. 提供可打开预览和已实现/未实现清单；提交成果，等待站主反馈。

### B：真实后台

1. 比较可行服务，给出推荐与费用、访问限制，确认影响产品的关键选择。
2. 接入认证、持久化内容、媒体上传、草稿预览与发布流程。
3. 所有管理员写操作在服务端验证权限；正确处理上传和发布失败。
4. 验证浏览器刷新、重新登录和应用重新启动后内容仍存在。
5. 实现稳定 ID 与发布状态变化；只保留后续事件扩展点，不默认启动 QQ 推送。

### C：上线

1. 配置部署适配器（如需要）、托管、构建与发布触发、环境变量。
2. 预生产验证后，提交正式发布结果供站主确认；获得明确发布指令后上线。
3. 设置基础错误日志，写明备份、导出、恢复与版本回滚流程。
4. 交付后台入口与使用说明；域名可以后接，不能阻塞功能验收。

### D / E：后续任务

独立分支实施，先确认评论身份方式或 QQ 目标类型，再选择服务与验证接口。保留现有数据身份，不重建内容 ID、不因接评论重写整个前台。

## 11. 验收矩阵

| 编号 | 场景 | 合格条件 |
| --- | --- | --- |
| A1 | 首页与详情 | 正确排序、稳定链接、无移动端溢出 |
| A2 | 图片与视频 | 图片完整查看，视频手动播放，加载失败可理解 |
| A3 | 主题与字体 | 三种主题可切换，刷新保留选择，字体失败可回退 |
| B1 | 登录与权限 | 访客访问写 API 被拒绝，不能靠隐藏按钮实现权限 |
| B2 | 草稿 | 公开列表、详情、Feed 和公开构建中均无草稿正文 |
| B3 | 发布与持久化 | 手机创建并发布，刷新/重新登录/重启后可读取 |
| B4 | 修改与撤回 | 修改不改变 ID；撤回后不再公开，缓存按方案失效 |
| B5 | 上传 | 超限与不支持格式明确提示，失败可重试，无管理密钥泄露 |
| C1 | 部署 | 真实网页可访问，代码更新可部署，失败有记录 |
| C2 | 可维护性 | 站主可独立编辑内容；备份能实际导出，恢复步骤可执行 |
| D1 | 评论 | 审核、删除、回复、权限与输入安全正确 |
| E1 | 订阅 | 有效身份订阅和退订，标签过滤正确 |
| E2 | 推送 | 对应内容版本上线后发送，草稿和普通编辑不发送 |
