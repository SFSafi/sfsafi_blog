# 站主写文与评论

写文入口 `/admin/write/`，列表 `/admin/posts/`，评论管理 `/admin/comments/`，通知状态 `/admin/notifications/`。

代码已实现 D1 文字动态/文章编辑、Markdown 预览、草稿、发布、编辑、撤回、归档与版本冲突保护。管理能力需配置真实 Cloudflare Access 才能在线使用；本地签名令牌验收不等于真实邮箱登录验收。原有样例自动首次导入，不覆盖已有行，不导入草稿，示例保留标识；现有阅览/赞踩/头像/地点数据不重置。

## 内容方案选择（2026-10-14）

| 方案                        | 适合之处                                        | 本项目代价                                                           |
| --------------------------- | ----------------------------------------------- | -------------------------------------------------------------------- |
| Directus 等成熟 CMS         | 完整编辑与权限体系、内容/媒体管理               | 需要新增 CMS 服务、数据库及登录/发布集成，部署与套餐另行评估         |
| 现有 Worker + D1 单人编辑页 | 复用已建立 D1 和 Access，稳定链接，文字立即可见 | 自维护有限编辑/评论逻辑；媒体存储/视频处理另接，不能当作完整通用 CMS |

此次选第二种限定单人写作方案，避免在站主仅需写文时新增服务账号。公开正文通过 ContentRepository 的 D1 适配器读取，Astro 提供布局、静态资源和客户端脚本，Worker 动态生成公开页面；无需为每次文字发布等待 Git 重建。未来如迁移成熟 CMS，应保留稳定 ID、权限与事件契约。

官方资料：https://developers.cloudflare.com/d1/ 、https://directus.io/docs/getting-started/overview 、https://developers.cloudflare.com/workers/static-assets/binding/ 。

## 登录配置（网页操作）

1. Cloudflare Zero Trust 创建仅站主邮箱 Allow 的 Access 应用，保护本站 `/admin/*` 和 `/api/admin/*`。不得使用 Everyone/Bypass；站主邮箱已由用户提供并配置为 Worker 的 OWNER_EMAIL。
2. Worker 控制台设置 ACCESS_TEAM_DOMAIN 与 ACCESS_AUD，按 deployment.md 获取真实团队域名和应用 Audience。不要在聊天中提供验证码、JWT 或账号密钥。
3. 写文、评论管理、通知管理在服务端重新验证 JWT 签名/issuer/audience/有效期，并核对 OWNER_EMAIL。其他登录邮箱不能写文；未配置时不开放写入。

Access 真实账号配置尚未验收。当前执行环境 wrangler whoami 明确显示未登录，无法代替站主建立账号内 Access 应用。若当前账号不支持 workers.dev 指定路径的 Access 配置，需按 deployment.md 使用受支持的域名或认证方案，不能放宽身份验证解决。

## 写文流程

- 选择动态或文章，填写标题（文章必填）、Markdown 正文、可选摘要/最多 8 个标签/手动地点/置顶。
- 先保存草稿；预览只返回经过限制的 Markdown HTML，不执行原始 HTML，图片 Markdown 暂不加载远程图片或绕过草稿媒体保护。
- 发布后正文、首页、文章列表、标签、站内搜索、分享与统计读取实际 D1 内容，链接为 `/posts/{id}/`。
- 已发布内容保存会立即更新；普通编辑不发送新的首次发布通知。多个编辑页冲突返回 409，需重新载入，不能覆盖较新版本。
- 撤回/归档后公开正文与公开 API 不再可读。归档保留数据，可重新发布，不直接永久删除文章。恢复保持原 ID 和首次发布时间，不重复创建首次发布事件。
- 正文上限 20000 字，标题 120 字，摘要 300 字，地点 80 字；请求体另限 64KB。正文媒体上传按用户要求暂缓，R2 未建立，视频自动转码未接通；不提供假的上传控件。

公开 HTML 不缓存旧正文；静态样例详情别名转到受数据库状态保护的规范链接，内部模板不作为公开阅读入口。仍需保留数据库/媒体备份，Git 不是内容恢复方案。

## 评论

访客无需作者账号，输入昵称和纯文本评论（最多 1000 字），支持一级回复，提交后直接公开。历史 pending 评论也按公开处理，原先隐藏/删除标记仍保持不可见。站主可在 `/admin/comments/` 删除评论、回复；服务端重新验证 Access 和 OWNER_EMAIL，不开放访客删除权限。站主昵称由服务器读取并标识，不能靠填写昵称伪造身份。

删除采用管理记录保留的删除标记，原评论及其回复不再公开；删除同时移除相关邮箱并取消待发通知。文章撤回后关联评论及邮件通知不可公开。版本检查保护并发操作。

邮箱为可选项，仅用于回复通知，不出现在公开或管理评论列表中。先确认邮箱订阅，再接收回复邮件，每封可退订；邮箱确认不影响评论立即公开。服务未配置时字段禁用，仍可正常发表评论。发信配置与状态见 [comment-email.md](comment-email.md)。

重复重试同一提交不会新增评论；匿名访客 Cookie 使用已有统计会话。默认每访客每分钟 2 次、每网络地址每小时 6 次、全站每日 100 次新评论，额度 SQL 原子预留。网络地址只存摘要/窗口计数，不存原始 IP；保留文本安全渲染及现有限流，不把直接公开当作解除防滥用限制。

本地真实 Worker/D1 的即时显示、站主删除、草稿/父评论隔离、浏览器评论、越权拒绝，以及邮件确认/去重/退订均有检查；模拟发信服务并不代表真实邮箱已收信。
