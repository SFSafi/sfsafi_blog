# 媒体上传与在线浏览需求

此文档记录站主最新要求。独立 FFmpeg 服务及仅站主视频转码页面已实现，部署方法见 [ffmpeg.md](ffmpeg.md)；R2、正文媒体绑定和公开视频发布尚未接通，图片压缩也未实现。当前公开正文媒体仍是示例，不能将以下完整流程称为已上线。头像的 512px/200KB 限制不能用于正文照片或视频。

## 读者体验

媒体以网页在线阅读/播放为目标。图片列表按显示尺寸加载缩略图，详情/图片弹窗显示足够清晰的阅读版本，不因保存了原素材而默认下载大文件。视频手动播放、支持移动端内联播放、封面、播放失败重试；播放源应支持 HTTP Range，避免完整下载后才能播放。保持图片比例，不自动裁掉正文照片。

## 上传选项

默认自动处理，无需站主每次手动点击“压缩”：选择图片后自动压缩为标准档，选择视频后自动转码为适合网页播放的标准档，并生成缩略图/封面。处理成功、显示结果预览后上传阅读/播放版本；若视频必须先传入临时处理区，则在转码完成、派生对象校验成功后清理本次任务的临时源文件，只有站主选择保留原素材才额外持久保存源文件。视频自动转码是正文上传正式上线的必要能力，尚未接通时不能把原视频上传当作完成自动处理。

站主仍可选择高质量/标准/省空间，或明确选择原素材；图片和视频均默认“标准”，“同时保留原素材”默认关闭。不把选项名称当作已验证的编码能力。

| 选项   | 图片初始处理目标                             | 视频初始处理目标                                                 |
| ------ | -------------------------------------------- | ---------------------------------------------------------------- |
| 原素材 | 原文件字节不变、原尺寸不变；另生成阅读缩略图 | 原文件字节不变；格式兼容时直接作为播放源，否则另生成兼容播放版本 |
| 高质量 | 最长边不超过 2560px，WebP 编码质量约 0.9     | 不超过 1080p，较高画质                                           |
| 标准   | 最长边不超过 1920px，WebP 编码质量约 0.8     | 不超过 720p，平衡画质/大小                                       |
| 省空间 | 最长边不超过 1280px，WebP 编码质量约 0.65    | 不超过 480p，优先小文件                                          |

以上是实现起点，不是质量或文件大小保证。编码质量数值、分辨率和视频码率含义不同，不能把图片的 quality 值直接当作视频压缩比。不放大小素材；最终尺寸受原素材限制。预览显示实际格式、大小与尺寸；视频还显示时长。目标格式应依据浏览器兼容测试确定，并提供兼容回退。

另提供“同时保留原素材”开关，默认关闭：选择压缩档位时，只有主动开启才额外上传并保存原始文件。选择“原素材”时必然保存原始文件，该开关显示为已选。压缩失败时保留浏览器中的文件，允许重新处理或明确切换原素材，不能静默降档、丢弃原文件或把重新编码的文件标为原素材。

默认只持久保存实际阅读/播放版本及必要缩略图/封面，减少重复大文件存储；不影响用户本地原文件或已有站内素材。不能保证所有输入都可变得更小，处理后更大时重新调整编码或提示，不以“压缩成功”掩盖存储增长。

上传前显示原始大小、处理后大小、节省比例、预览与预计上传内容；保留原素材时明确显示两份素材占用的存储。压缩结果更大时提示并允许切换原素材。处理/上传都有进度、取消、失败原因及重试；文件大小和格式限制在选择及服务端都校验。不要在未上传成功前把临时预览标为已保存。

## 格式与处理边界

图片需处理拍摄方向、透明度和动图：保留原素材保持文件字节；压缩档位纠正方向，透明图不得被无提示地转成黑底/白底；动图不支持保留动画的压缩时明确说明，不能静默只留第一帧。原素材可能含 EXIF 等元数据，上传前提示；压缩版默认去除非必要元数据。

视频压缩需要真实解码/编码与音轨处理，不能只改后缀、quality 参数或播放器显示尺寸。默认自动转码的初始目标为 H.264 视频 + AAC 音频的 MP4，并将播放索引移至文件前部（fast start）；可依据实际播放兼容与成本测试调整。转码链路未接通时，正文视频自动上传不可用，并说明原因；如提供兼容原素材上传入口，必须由站主明确选择“原素材”，不能自动回退上传原视频或宣称压缩完成。超出网页播放兼容范围的原视频要完成派生播放版本后才允许作为可播放媒体发布，不能宣称所有原始格式都能在线播放。

第一版不建设长期转码集群。结合 CMS/存储选型评估浏览器处理或托管转码，验证手机稳定性、音画同步、处理时长、资源/费用后再确定视频参数。未经明确授权不启用付费转码服务。

## 存储与内容状态

真实正文媒体使用持久对象存储或 CMS 媒体库，不进入 Git，不使用 Codex 临时目录，不沿用 D1 的头像 BLOB 容量方案。分别保存原始对象（仅在选择保存时）、阅读/播放版本和缩略图/封面引用及处理状态；设置稳定媒体 ID、MIME、实际字节数、尺寸、时长与替代文字。草稿媒体的访问保护须与草稿正文一致，不能提前公开链接。

只接入站主上传，服务端验证登录、文件内容与大小。创建、上传、转码、发布及失败状态分开，未完成素材不能被当作可用内容发布。删除原素材或替换派生文件前检查内容引用；备份覆盖实际保存的原始和派生对象，而非仅备份数据库路径。存储具体额度、最大文件大小及恢复验收依赖后续选型，不预先承诺无限容量。

## 必须验收

- 默认上传流程会自动触发图片压缩/视频转码，无需额外点压缩；默认不额外持久保存源文件；任务临时文件仅在派生版本成功后清理，处理失败不伪装成功。
- 选择原素材时，存储文件校验和与本地原文件一致；开启“同时保留原素材”时两份素材均存在，关闭时不额外保存原始对象。
- 不同图片档位实际改变输出尺寸/质量；原图比例、方向、透明度正确；失败/动图不支持时有明确说明。
- 视频档位有实际转码、保持音轨与同步；未接通转码时选项不可用且解释明确；原始不兼容视频不能伪装成可播放。
- 上传前后实际大小/尺寸一致；取消、超限、失败重试及刷新后持久化可验证。
- 手机与桌面在线查看、播放和跳转进度正常；管理员未授权上传被拒绝，草稿素材不公开。
