# 站内 AI 搜索

公开页面 `/search/`，导航“搜索”；接口 `POST /api/search`，同源 JSON `{ "query": "关于 Astro 建站的内容" }`。`GET /api/search` 只返回 AI 是否已配置，不返回地址、模型或密钥。问题限制 200 字，请求限制 2KB。

## 站主只需网页配置

Cloudflare 控制台 → Workers & Pages → sfsafi-blog → Settings → Variables and Secrets：

| 名称 | 类型 | 填写方式 |
| --- | --- | --- |
| AI_API_KEY | Secret（加密） | 你的模型服务 API Key，不发到聊天、不使用 PUBLIC_ 前缀 |
| AI_BASE_URL | Text | OpenAI 兼容服务根路径，例如 https://api.openai.com/v1，不要附加 /chat/completions |
| AI_MODEL | Text | 服务商实际支持的模型 ID |
| AI_DAILY_LIMIT | Text，可选 | 每 UTC 日全站调用上限，默认 100；0 暂停，最高 10000 |

保存并部署配置后即可生效；keep_vars 保留控制台变量。使用支持 `/chat/completions` 的 HTTPS 服务，文本回复须支持按提示输出 JSON（不要求 response_format 或工具调用）。Anthropic 原生 Messages API 等非兼容协议不能直接使用。若仅测试本站模型，可暂把上限设为 5，检查结果与服务商用量，再调整。没有自动开通任何模型服务或付费套餐。

API 调用由站主的模型账号计费。每日次数限制不等于金额封顶，实际成本还取决于输入/输出与服务商价格；建议同时在服务商设置金额上限。调用失败也占用预留次数，避免失败重试造成额外消耗。每日额度按 UTC 重置，每网络地址每分钟最多 6 次；额度预留使用真实 D1 原子操作，跨实例共享。网络地址仅保留 SHA-256 摘要及当前窗口计数，不保存查询日志；摘要不等于不可识别匿名数据。公开接口并非完整防刷系统。

## 内容与回答

只通过 ContentRepository 查询已发布公开内容，最多扫描 1000 条；关键词/中文双字匹配排序，最多 8 条、每条正文 1000 字发给模型，输出最多 700 tokens。小站中语义问题即使没有关键词匹配也会给模型相关候选；内容规模扩大时应升级全文索引/向量检索，当前不承诺搜索所有超出扫描上限的历史内容。

服务端提示要求仅依据资料回答，限制模型提供的 sourceIds 必须属于候选集合；不允许草稿或外部地址作为引用。所有回答与摘要在浏览器作为纯文本显示，不执行 HTML/Markdown。引用约束不能保证模型每句话正确，页面提醒以原文为准。读者问题和候选公开内容会发送给所配置的第三方服务，页面明确提示不输入敏感信息。

未配置、配置异常、额度耗尽、上游非成功状态、15 秒超时、回复超过 32KB、JSON/引用无效均回退关键词结果；不会把供应商错误正文或密钥输出给读者。无关键词匹配显示空状态。按 IP 限流返回 429，可一分钟后重试。

初始自动建表机制增加纯新增 `0004_search.sql`，保留原有统计/资料/地点。仅新增 search_usage 表，无数据删除。未配置模型时关键词搜索不会发起模型请求，也不会消耗模型额度。

## 验证范围

本地 Miniflare 真实 Worker/D1 与受控的 OpenAI 协议响应测试覆盖公开内容隔离、参数/来源校验、关键词、引用验证、额度/限流和浏览器搜索结果/四种宽度；不把夹具测试称为真实供应商模型验收。站主 API 尚未提供，真实模型计费及结果需要配置后复验。
