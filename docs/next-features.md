# 后续功能：站主写文、评论与 QQ Bot

站主明确要求后续增加这些功能。本文件是开发/部署范围与验收约定，不是已实现清单。后续已开始实现：D1 文字写文与评论/审核已部署但站主登录待配置，QQ 签名更新接口与独立 Worker 已准备；真实 Access 登录及 QQ Bot 部署/投递待账号配置。状态详见 writing.md、qq-bot.md 和 progress.md，下面保留原验收范围。

## 1. 仅站主可用的写文页面

规划 `/admin/write/` 写文与 `/admin/posts/` 文章管理；支持手机和桌面操作，Markdown 编辑与预览、草稿保存、发布、编辑、撤回，手动地点、标签、图片和视频。正文媒体按 media-upload.md 默认自动压缩/转码，保留原素材为可选。

所有创建、保存、上传、发布、撤回、删除接口在服务端验证唯一站主身份。管理路径与 API 使用站主专属登录/Access 应用，写接口还需对照已配置的站主身份；访问页面、知道 API 地址或拥有普通评论身份均不获得发文权限。未经认证的访客与其他已登录身份必须被拒绝，不提供其他作者注册、邀请写文或访客投稿。

内容持久化与草稿预览不能靠浏览器 localStorage；公开查询始终只读取 published/public，草稿正文及草稿媒体不能进入公开构建或公开链接。保持现有稳定 ID 和 canonicalPath；版本校验防止多个编辑页覆盖，保存/发布失败可重试。管理页显示“已保存草稿”“发布处理中”“该版本已上线”等真实状态。

验收重点：只有站主能写；普通访客/评论者不能借接口写文；草稿隔离；刷新后保存仍存在；手机编辑、媒体处理与发布流程真实可用。

## 2. 评论

已发布内容详情页提供评论/回复/分页。评论与写文权限分离，评论者只能提交评论，不能修改文章、上传正文媒体或操作后台。评论者身份方式在实施时确定，不默认要求 GitHub 账号或开放作者账号。

默认评论进入待审核状态，只有已审核且关联内容仍公开的评论出现在前台。站主在规划 `/admin/comments/` 审核、回复、隐藏、删除；写入文本按安全规则显示，提供长度限制、速率限制与反垃圾。被撤回的文章不会因评论查询泄露正文或草稿；不能用前端隐藏按钮代替服务端权限校验。

验收重点：待审核内容不公开；危险 HTML 不执行；回复正确关联；站主管理权限与普通评论权限分别检查；审核/隐藏与刷新后持久化真实有效。

## 3. 网站到 QQ Bot 的更新接口

网站发布流程生成持久化更新事件，由服务器通知独立 QQ Bot 服务。规划 Bot 接收端为 `POST /site-updates`，不是读者可以随意调用的发消息接口；最终路径随部署实现确定。第一版不提前开放未实现的端点。

事件包含 eventId、postId、revision、eventType、occurredAt，以及公开标题/摘要、标签和稳定站内链接。不传草稿、站主密钥或完整大视频。默认只有首次发布触发通知，普通修改不重复推送；后续“修改并通知订阅者”需要明确选择。

发布数据成功不等于内容已上线。静态部署必须核验该 postId/revision 实际可访问后才通知；构建失败不发送，重试也不能把旧版本当成最新版本推送。

网站与 Bot 间使用服务端鉴权/签名，校验请求时间并按 eventId 去重；密钥在各自部署环境的 Secret 中保存。Bot 收到通知后持久化待发任务，再返回接受状态，不能以一次内存循环或 HTTP 200 宣称 QQ 已投递。投递唯一键为 eventId + subscriptionId，指数退避、失败记录、重试与退订跳过规则沿用 requirements.md 第 8 节。

订阅、退订、查看订阅和标签筛选通过所选 QQ 平台验证过的用户/会话身份完成。群订阅需要合法的群授权，不能靠输入任意 QQ 号或任意成员操作订阅整群。

## 4. QQ Bot 部署也是交付范围

必须交付独立运行的真实 QQ Bot，而不只提供一段发送函数。选择受支持的官方机器人平台，实施前核实账号申请/审核、群或私聊渠道、主动消息窗口/频率、SDK 与部署方式。当前尚未确定群推送还是个人订阅，以及对应平台是否支持；不预先承诺任意群/任意好友主动推送，不静默采用个人账号协议替代。

如果平台需要常驻连接，Bot 部署在支持常驻进程的运行环境；不能把 Codex 开发机或短请求 Worker 当成持久 Bot。交付项包括凭据安全注入、启动/重启、健康检查、日志、投递任务持久化、备份与恢复说明、部署更新和故障排查。实际选型后才能核实成本，未经授权不启用付费服务。

验收必须包含真实站内发布上线 → 产生一次事件 → Bot 收到并持久化 → 实际受支持 QQ 目标收到通知，以及订阅/退订、重复事件、断线/重启后任务保留、失败可追踪与重试。Mock 通过不能替代真实 QQ 投递验收。

## 开发顺序

1. 确定内容/媒体存储与编辑方案，完成站主身份配置；先交付站主写文与发布流程，并接通自动媒体处理。
2. 添加评论与审核，保持发文权限仅属于站主。
3. 实现持久发布事件、上线确认和 Bot 签名接收接口。
4. 确定 QQ 目标渠道/账号与云端运行方式，部署 Bot 并完成真实订阅和投递验收。

各阶段交付独立可验证结果，保留现有公开统计、分享与站内搜索。外部账号配置、真实存储/转码及 QQ 渠道权限仍需在实施时落实，不把未来要求标为当前功能。
