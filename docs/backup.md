# 写作备份与文字恢复

入口：https://sfsafi-blog.uk/admin/backups/ ，只有站主邮箱通过 Access 验证后可操作。

## 下载

点击“下载 JSON 备份”，文件名包含导出日期。格式 `sfsafi-writing-archive`、版本 1，最多 5000 条/5 MiB；超限时明确拒绝，不悄悄截断。建议每周及批量修改前导出一次，保留最近 5 份与重要节点。当前为站主手动下载，没有自动备份计划；文件含私有草稿，应自行妥善保存。

包含所有动态/文章、正文格式、原 ID、日期、状态/版本、回收站标记、标签、地点覆盖、媒体引用，以及网站文案和公开个人文字资料。媒体引用是描述/路径，不包含原图片、视频或头像字节。评论、统计、访客记录、邮箱订阅、邮件与 QQ 队列、服务密钥不包含在文件里。

## 找回文字

1. 选择本站导出的 JSON 文件；浏览器校验格式、版本、大小及文字字段。
2. 在列表里选中一篇内容，查看文字预览。
3. 点击“恢复为新草稿”，再点“打开恢复的草稿”检查和编辑；需要公开时自行发布。

恢复通过已有受保护发文 API 保存到 D1，新 ID、当前创建时间、草稿状态，不覆盖原内容，不复制统计/评论，不触发发布推送。保留 plain/Markdown 正文格式、标题、摘要、标签和地点；置顶默认关闭，媒体附件不恢复。网站文案与个人资料随文件导出用于留存，但当前不会自动导入覆盖在线设置。请求失败后再次点击使用同一恢复 ID，已有相同草稿可继续打开。

如果原记录仍在回收站，优先从“文章与动态 → 回收站”恢复，这会保留原稳定链接与历史数据。JSON 导入用于找回文字的副本，具有新的链接。多篇内容可以逐篇选择恢复，不提供一键覆盖数据库的操作。

## 完整数据库与媒体恢复

写作 JSON 不能替代完整 D1 导出、媒体对象备份或灾难恢复。完整 SQL 导出仍应使用 Cloudflare D1 控制台/受支持的 export 命令，包含正文、资料头像、统计、评论、私有通知与 QQ 表，并按账号预算定义保留策略。当前没有配置或验收生产完整备份计划，不称其已自动生效。

本轮已在真实本地 Workerd/D1 与 Chromium 验证下载、文件读取、原记录不变、plain 正文保留、恢复草稿对公众 404、权限拒绝、非法文件拒绝和进程重启后保留；没有导出或恢复实际生产私有数据。
